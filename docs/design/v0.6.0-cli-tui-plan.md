# v0.6.0 CLI/TUI 演进计划

> 状态：执行中（2026-09-22 建立）
>
> 基线：v0.5.0 已发布；v0.6.0 只演进 CLI/TUI 与共享 core，GUI 保持维护模式。

## 目标

1. TUI 首屏同时展示所有账号的使用状态、令牌健康和已加载配额，减少逐账号移动才能比较信息的成本。
2. 统一 access token 有效期判定，以 JWT `exp` 为第一依据、本地 `expires_at` 为回退。
3. 刷新失败时保护官方登录态：只有仍可使用的 AT 才允许继续投影；过期 AT、缺 RT 或鉴权失败均不得覆盖 `auth.json`。
4. 显式报告 harvest 结果，避免命令在收敛失败时仍报告成功。

## 范围与非目标

- 不修改 `Account`/`AccountsFile` 的持久化字段，不要求数据迁移。
- 不修改 OAuth client、回调端口、redirect URI 或授权范围。
- 不引入守护进程，不做后台定时刷新，不自动刷新全部账号的 RT。
- 不新增 GUI 功能；共享 core 行为需通过 GUI 现有回归测试。
- 不在 v0.6.0 持久化配额历史；TUI 只显示本次会话已加载的数据与查询状态。

## 架构与状态契约

- `hangar-core::token_health` 是纯规则边界：输入 AT、RT、账本有效期、stale 与当前时间，输出令牌健康快照；不读写文件、不联网。
- `account` 继续拥有账号库锁、刷新编排和官方投影。刷新后严格保持 S11：先保存账号库，再投影官方 `auth.json`。
- OAuth 层返回结构化刷新错误；账号层只依据错误种类决定是否 stale，不再匹配错误文案。
- TUI overview 只消费账号、令牌健康与内存配额快照，不复制刷新规则。

令牌健康状态：

| 状态 | 含义 | 切换行为 |
|------|------|----------|
| `fresh` | AT 超出 5 分钟偏斜窗口 | 可直接投影 |
| `expiring` | AT 在 5 分钟内到期 | 先刷新；临时失败则拒绝切换 |
| `expired` | AT 已到期 | 必须刷新；无 RT/失败则拒绝切换 |
| `unknown` | AT 非空但无法得到有效期 | 保持兼容，可投影；doctor/TUI 明示未知 |
| `missing` | AT 为空 | 拒绝投影并要求重新登录 |
| `stale` | RT 已被服务端明确拒绝 | 拒绝投影并要求复活 |

## 验收标准

- 两个及以上账号无需移动光标即可比较状态、计划及已加载的主要配额窗口。
- 未加载配额显示“未知/待查询”，失败显示“失败”，不得把缺失值渲染成 `0%`。
- JWT `exp` 与 `expires_at` 冲突时，刷新决策以 JWT 为准。
- 目标 AT 过期或临期且无法刷新时，切换失败，官方 `auth.json` 内容保持不变。
- OAuth 明确拒绝 RT 时标 stale；网络/超时等临时错误不误标 stale。
- 显式 `harvest` 失败必须返回非零；启动期 best-effort 收敛可继续但不得谎报成功。
- JSON 输出不包含 access/refresh/id token 字段或值。
