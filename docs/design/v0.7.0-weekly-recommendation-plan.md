# v0.7.0 周额度总览与账号建议计划

> 状态：已发布（2026-09-22；[GitHub Release](https://github.com/mocikadev/hangar/releases/tag/v0.7.0)）
>
> 基线：v0.6.0 已发布；本轮只演进 CLI/TUI/classic 与共享配额读取路径，GUI 保持维护模式。

## 目标

1. TUI 启动后后台顺序查询全部正常账号，让 7–8 个账号的周剩余额度无需手动逐个加载即可比较。
2. 所有用户界面明确使用“周剩余”语义，不再展示当前未生效的 5h 窗口。
3. 基于本次会话已成功查询的周剩余额度给出稳定、可解释的账号建议，但绝不自动切换。
4. 保持现有按需 Token 刷新与 S11 写入顺序，不增加后台定时刷新或额外持久化。

## 范围与非目标

- Core 继续容错解析服务端下发的所有窗口，但 TUI/classic 只展示周窗口。
- 启动查询保持单后台线程顺序执行，不引入并发、缓存或新的账号字段。
- 推荐规则位于 CLI 私有纯模块，不联网、不写文件、不刷新 Token。
- classic 的“配额”入口同步输出全账号周剩余和建议；一次性 quota 的人类输出也只展示周剩余，JSON 继续保留完整容错窗口契约。
- 不新增 `recommend` 子命令，不做自动切换、配额历史、GUI 功能或版本升级。

## 推荐契约

1. 只考虑非 stale 且本次会话已取得已知周剩余额度的账号。
2. 周剩余最高者是候选；相同值优先当前账号，否则保持账号库顺序。
3. 当前账号有已知周剩余，且与最高值相差不超过 10 个百分点时，建议继续使用当前账号。
4. 差距超过 10 个百分点或当前账号无有效数据时，建议最高候选。
5. 查询未完成、失败、未知均不产生虚假 `0%`，也不进入推荐。

## 验收标准

- TUI 宽屏与窄屏都不再出现 5h 配额列，周数据明确标为“周剩余”。
- 启动后所有非 stale 账号进入查询队列，查询期间仍可移动、过滤和退出。
- 推荐只在已知周剩余之间计算；阈值和同值规则具有纯单测。
- 推荐只改变展示，不调用切换、刷新或任何写路径。
- 单账号查询失败不影响其他账号；失败与未知不显示为 `0%`。
- 配额查询导致按需刷新时，新 RT 仍先写账号库；非当前账号不得覆盖官方登录态。
