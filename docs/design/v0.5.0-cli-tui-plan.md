> 状态：实现与本机验证完成（待提交；未升版本、未发布）
>
> 基线：v0.4.0 已发布；账号一致性、OAuth、配额和 TUI 已稳定。

> 目标：不扩展 GUI，在不改变凭据格式和 S11 写入不变量的前提下，补齐可脚本化一次性 CLI，并改善 TUI 配额交互。

## 范围边界

- 一次性 CLI 与 TUI 是 v0.5 新能力主入口。
- classic 保留现有交互和兼容 flags，不继续承载复杂新交互。
- GUI 保留在 workspace/CI，进入维护模式，不要求 v0.5 功能对等。
- 不改 `Account`/`AccountsFile` 持久化结构，不改 OAuth 常量，不新增 provider、守护进程、配额历史或钥匙串迁移。
- 本轮实现完成不等于授权升级版本号、打 tag 或发布。

## 命令契约

```text
hangar list [--json]
hangar current [--json]
hangar switch <完整ID|唯一邮箱> [--json]
hangar login [--json]
hangar reauth <完整ID|唯一邮箱> [--json]
hangar remove <完整ID|唯一邮箱> --yes [--json]
hangar quota [<完整ID|唯一邮箱>|--all] [--json]
hangar doctor [--json]
hangar harvest [--json]
hangar update [--json]
hangar tui
hangar classic
```

退出码：`0` 成功，`2` 参数错误，`3` selector/状态守卫失败，`4` 凭据需重新登录，`5` 网络或外部服务失败，`1` 其他内部错误。

## 完成定义

- 未知参数不再静默忽略；无子命令仍保持默认 TUI/非 TTY classic 行为。
- 所有 JSON 都由脱敏 DTO 显式构造，仓库测试证明不含 token 字段和值。
- selector 不以列表编号作为脚本契约，不存在或歧义时不产生写副作用。
- 删除没有 `--yes` 时失败且不等待 stdin。
- 一次性命令执行前不自动更新自身。
- 自动化门禁全绿，TUI 终端冒烟覆盖启动、移动、命令面板和退出。
