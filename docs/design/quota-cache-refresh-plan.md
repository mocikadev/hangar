# 配额快照与刷新计划

> 状态：功能已实现，macOS 真实账号隔离验收完成（2026-09-23）。适用 CLI/TUI、macOS 原生 GUI 与共享 Core；Linux GUI 待在 Linux 主机实现时接入同一 Core 契约。

## 目标与边界

- 启动立即显示上次成功的周配额；30 分钟内不因再次打开而重复请求。
- 到期后后台按账号库顺序刷新；手动刷新强制请求；失败时保留上次成功值并显示时间和失败状态。
- GUI 驻留期间定期检查到期时间，唤醒后检查一次；完全退出后不运行守护进程。TUI 前台运行期间也检查到期时间；一次性 `hangar quota` 保持实时查询。
- 仅使用新鲜且周剩余已知的配额计算稳定推荐；推荐不触发切号。
- 配额快照与凭据分离。当前数据量只需版本化 JSON，不引入 SQLite；历史曲线或独立后台采集有真实需求时再评估数据库。

## 数据与流程

- 路径：账号库同目录的 `quota-cache.json`，schema 版本 1，按稳定账号 ID 保存一份最新成功的脱敏配额和 `fetched_at`。不含 AT/RT/ID token、HTTP body 或错误详情。
- 写入：权限 600、原子替换；写时重新读取并按时间戳合并，避免 CLI 与 GUI 的旧快照覆盖新快照。损坏/不兼容版本视为空缓存，后续重新获取；不触碰账号库或官方认证文件。
- 有效期：30 分钟；未来时间戳视为待刷新。成功响应即使缺少周窗口，也有 30 分钟冷却，避免非公开接口字段临时缺失时反复请求；未知值不进入推荐。失效账号不显示旧配额。缓存旧数据仍可显示，但明确标“过期”。
- 自动刷新：先收敛官方 `auth.json`，再查到期账号。配额请求沿用 Core 的按需 AT 刷新及 S11 写入顺序；不新增独立 RT 定时刷新。各端同一进程中不叠加刷新轮次。
- 手动刷新：跳过有效期，按账号库顺序查询全部非失效账号。单账号失败保留缓存，其他账号继续。成功后立即写缓存并更新卡片。
- GUI/TUI：分别保有界面任务和计时器，Core 拥有缓存格式、有效期和推荐筛选。关闭窗口但仍驻留的 GUI 可继续调度；退出进程停止。TUI 退出即停止，不新增服务。
- macOS GUI 的卡片与状态栏菜单使用同一展示顺序；逐账号刷新期间固定位置，整轮结束后才依据最新快照重排，不修改账号库的刷新顺序。
- 推荐：仅新鲜成功的已知周配额参与；旧配额只供参考。一次刷新失败时不得把旧值当成实时推荐。

## 验收

1. 第二次打开 TUI/GUI，30 分钟内立即显示缓存且无自动配额请求；手动刷新仍发起请求。
2. 过期或首次使用时先显示旧值，再逐账号更新；失败后旧值仍在，且明确为过期/失败。
3. CLI 与 GUI 对同一文件并发写不会回退较新的账号快照；不含凭据。
4. 推荐不使用过期、失败、失效或未知的周额度；任何刷新或推荐不自动切号。
5. 任何测试写路径只在隔离 HOME/CODEX_HOME 执行；真实账号请求需用户在真机验收。
