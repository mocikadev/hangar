# v0.4.0 收口计划

> 状态：v0.4.0 已发布；Windows 产物与剩余 macOS 人工项继续延期跟踪
>
> 基线：v0.3.1 已发布；`main` 已包含“添加不切换”、激活账号刷新投影和系统托盘。
>
> 目标：停止扩展新功能，完成权威文档、关键回归测试、Linux/macOS 托盘、跨平台 CI 门禁和发布链路收口后发布 v0.4.0；Windows 产物延期。

## 已确认的平台状态

- Linux 托盘菜单：已由用户真机验证。
- macOS 托盘：Apple Silicon DMG 已完成关闭驻留、菜单恢复、托盘退出与 Cmd+Q 验收；浅/深色和托盘切号仍待确认。
- Windows 托盘：本轮不做真机验收、不发布 Windows 资产；代码保留并继续由 Windows CI 编译检查，延期到后续版本。
- GUI 与 CLI 默认共享 `~/.hangar/accounts.json`；`CODEX_HOME` 仅影响官方 Codex 目录。隔离测试不得读取或写入真实账号数据。

- 自动化门禁（隔离 `HOME`/`CODEX_HOME`）：先执行 `cargo fmt`，再执行 `cargo clippy -- -D warnings` 与 `cargo test`，全部通过；共 48 个测试（CLI 7、core 28、GUI 13）。另行执行过 workspace/all-targets 版本的 clippy 与测试，同样通过。

- macOS Apple Silicon：`cargo build --release -p hangar-gui` 与 `cargo tauri bundle --bundles dmg --ci` 成功，生成 `hangar_0.3.1_aarch64.dmg`；从 DMG 以隔离目录启动成功。
- macOS 红色关闭：首次验收发现关闭事件只在 `ui()` 拦截会导致进程退出；移至 eframe 始终运行的 `logic()` 后重新打包复验，窗口与应用级 Dock/窗口条目消失，进程持续驻留。
- macOS 账号路径：代码审计确认 GUI/CLI 均通过 core 的 `accounts_file_path()` 读取 `~/.hangar/accounts.json`，`CODEX_HOME` 只决定官方 Codex 目录；本轮 GUI 空列表来自刻意使用隔离 HOME，并非两套默认路径。
- macOS 真实数据复验：经用户明确要求，以正常 HOME 从 DMG 启动后 GUI 识别到账号库中的 2 个账号及使用中状态，确认不存在 GUI/CLI 默认路径分叉。使用中账号原本已标记 stale，且记录的 access token 已过期；启动收敛不会设置 stale，自动配额刷新也会跳过 stale 账号，因此该状态不是本次 GUI 启动造成。
