# 项目 Spec：hangar（原 codex-switcher）

> Codex 多账号切换 CLI/TUI 工具。本文档是需求与验收的唯一权威入口。

## 目标

让使用 OpenAI Codex 的用户在多个 ChatGPT 账号间**免重复登录**地切换：

1. 切换账号 = 一条命令/一次按键，秒级生效
2. 账号凭据长期保活：官方 Codex 轮换 refresh_token 后自动收敛，不失效
3. 官方 `auth.json` 是唯一权威（Authority），本工具只是缓存与投影

## 用户场景

| 场景 | 用户动作 | 期望结果 |
|------|----------|----------|
| 多账号切换 | 选中账号回车 | 官方 auth.json 被投影为目标账号，Codex 重启后生效 |
| 长会话后切回 | Codex 运行数小时后切回该账号 | harvest 自动回收官方轮换的新 RT，切换成功不要求重登 |
| 账号在 Codex 侧重新登录 | 用户手动 `codex login` | 下次打开工具自动收编为新账号（S5） |
| RT 失效 | 服务端撤销/轮换链断裂 | 账号标 stale，拒绝投影污染官方登录态，定向复活 |
| 配额速览 | 打开配额面板 | 每账号显示窗口剩余 % 与重置时间、重置卡数量 |
| 异常排查 | 自检 | 离线输出凭据完整性/权限/一致性问题清单 |

## 范围

**做：**

- OAuth（chatgpt 模式）账号的登录、切换、复活、删除
- 官方 auth.json 的 harvest（官方→库收敛）与投影（库→官方 merge 写）
- macOS keychain 快照同步、config.toml 自定义 provider 清理
- 配额查询（wham/usage，非公开契约）与重置卡只读展示
- 双前端：全屏 TUI（默认）与经典菜单（管道/--classic 回退）

**不做（非目标）：**

- API-Key 模式账号管理
- 核销重置卡（consume 属破坏性操作）
- 配额历史的持久化与图表
- Windows/Linux 系统钥匙串加密存储（明文 + 权限收紧是当前安全模型）
- 管理官方 config.toml 的其他配置项

## 关键约束

- 凭据为明文存储：目录 `700`、文件 `600`；错误日志只记 `status+error_code+body_len`
- `refresh_token` 轮换敏感：任何"先写官方后写库"的顺序都可能造成 RT 丢失（S11 先库后官方）
- `redirect_uri` 必须严格匹配官方 Hydra 白名单：`localhost:{1455,1457}/auth/callback`

## 验收标准

1. **免重复登录**：官方轮换 RT 后（真实场景或模拟），工具切换任一账号无需浏览器重登
2. **收敛安全**：harvest 不接受过期 id_token；空 AT 账号拒绝投影并标 stale
3. **守卫完备**：切换/删除"使用中"账号被拦截且不产生任何写官方文件的副作用
4. **登录成功率**：标准 OAuth 流程在 1455 或 1457 至少一个端口可用时一次通过
5. **崩溃恢复**：accounts.json 损坏时从 .bak 自动恢复；原子写不留半截文件
6. **回归验证**：`cargo test` 全绿（当前 20 个单测），TUI/classic 双前端真机冒烟通过
